# 正转邪路线：数据、证据与验收

基线：`494c72d`，2026-09-22。此次独立数据文件为 `public/cult-revisions.mjs`，导出 `CULT_REVISIONS` 和 `CULT_ADDITIONS`。本文记录数据实现、已接入契约与限定验收，不把节点齐全称为原作全流程达标。

详细定位见 [招揽参考记录](recruitment-reference.md)。本次只使用现有记录，没有重新提取或保存原版内容。新增对白、标识、战斗属性和场景演出均独立编写。

后五段都设置 `requireStaging:true`，不能仅播放日志摘要后完成；`before` 留一行独立入场文字供日志/质量检查，舞台负责实际演出。`after` 仅记录发生的事实，不能代替可见动作。

后五段另以 `requiredFlags` 核对上一事件完成旗标；终章同时要求真儿、眉儿已离开。每项有对应 `requirementText`。运行时已在开始舞台与提交完成时检查，防止直接调用或异常存档绕过武当、授职、先后两处牢位和告别。

所有新增任务及 g15 都显式 `xp:0,money:0`，避免通用任务默认奖励。武当没有逐人金钱、经验或击杀计数奖励，但完成任务仍沿用网页战斗补给：金创药 +1、补气丹 +1。这是网页设计，不是原版掉落认证；不能称整个接受链零物品变化。后五段没有敌人配置，也没有物品、金钱、经验、技能或选项奖励。

## 三次拒绝契约

`g15.refusalRule` 为 `{limit:3,outcome:'continue',key:'g15',refuseIndex:1}`，计数必须使用独立 `refusal_g15` 状态，不能共用 e05/e07 或蔷薇四拒的计数。

- 第一次拒绝：保存计数，显示 `refusalAfter`，仍在本次招揽。
- 第二次拒绝：保存计数，显示 `lastRefusalAfter`，进入最后一次答复。
- 第三次拒绝：此时才应用拒绝选项的 `moral:+2`，播放拒绝专属后续，完成 g15；无致死状态，无入教旗标。
- 任意轮接受：只设置 `cultPath`，播放接受专属后续，再前往武当；此前拒绝不提前增加道德。
- g15 公共 `after` 为空；两个选项各有专属后续，因此接受不会播放“纳兰离开、留楼救人”的对白。

旧选项中的 `ending:'cult'` 已从覆盖数据移除。必须整体替换 `choice`，不要把旧接受选项的 ending 逐字段合回。读档或重复完成不得再加道德、重复选边或跳到结局。

## 武当双阵营数据契约

`gCult_wudang` 使用 `type:'battle',count:1`，完整名单放在 `skirmish.enemies/allies`。运行时必须以 `skirmish` 分支产生角色并计算清场，不能把外层 count 当作一人战，也不能把 39 填回旧通用人数上限。

- 敌方 39 条，名字与重名次数见 [参考名单](recruitment-reference.md)。`清虚` 有两条且 ID 不同。
- 友方是纳兰一条及无忧教男弟子 26 条。合计 66 个稳定且不同的 ID，用于存档、阵营、存活和清场计数。
- 天星、张惟宜及友方纳兰标记 `boss:true`，这是网页强弱设计标记，不是原版 boss 属性复制。
- 名单排列不代表原版生成顺序，未导入原版坐标、属性或人物资源。
- 玩家和友方均可造成敌方死亡；任何死亡只登记一次。友方伤亡不能减少“剩余敌人”，也不能当敌人战利品结算。
- 未清完不得授职；普通失败、重试、刷新、离场和载入不能提前设置 `cultWudangCleared`，也不能漏算友军击杀。

## 舞台与存档提交边界

舞台模块使用相同的后五个任务 ID；其 actor、cue、位置、姿势和当前步骤可以在演出中保存。**任务死亡/离去旗标只由任务完成后的 `rewards.flags` 提交**，不能在镜头进行一半时让主线越过后续节点。

处决演出内先显示攻击，再显示受害者倒下；刷新应从舞台状态续演。第二段开始时蔷薇已经倒下，完成后两人均保持倒下。离开地牢又返回时不得把两人恢复为站立交互目标。告别结束后不能留下真儿或眉儿的常规跟随分身。

`gCult_epilogue` 的结局结算须在完整舞台 `release` 后执行。剧情中的纳兰身故不是一场新增 boss 战。收尾允许独立时间过渡，不需要为原本的结局叙述增加跑腿或练功刷怪。
