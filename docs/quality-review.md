## 为什么旧验收无效

本轮开始时，135个任务能在模拟引擎中推进到结局，但115处前置对白只是重复任务指令，74处结尾使用“此间事了”等占位话。75个地图数据均无障碍，环境只按5张旧背景轮换。这证明了流程数组可以走通，不能证明原作事件、因果、地图或游戏体验相符。

基线数据保存在本地 work/quality-baseline.json；本文件保留结论，临时日志不随静态站点部署。

1. **事件资料复核。** 按2001年正式版攻略与较详尽的后续流程逐项对照。修正洗剑池敌人数、武当先弟子后张惟宜、卓非凡友好一对一、箫声与揭名时间、木匣拒收后的取得、真儿保护杨影枫、孟知秋剧情败局及后段敌我身份。142个事件都有来源记录；重写对白是改编，未标为原作台词。

5. **人物与复拍。** 真实客栈和庭院截图暴露老板/商人/道士都套用主角。新增8类常见NPC图集，用共享姓名/身份映射接入场景及对话。主角和原有女同伴保持各自图集，未知角色仍有复用，未宣称人物原貌已还原。

## 验证的实际范围

- 自动模拟：六条长线结局×两种难度，以及开局特殊结局；142事件的界面运行和场景引用。
- 地图检查：75个地点，380处主线、出口和探索点的接近路径；逐线段检查不穿障碍。不同统计口径的布局数量只用于发现过度复用，不作为还原率。
- 状态检查：宝箱一次领取、搜索对象身份随存档保留、潜水超时重新尝试、八层全开才可救人、旧数字任务索引迁移、分支对白时序、机关重复奖励。
- 真实浏览器：用独立Chrome会话从祭父经酒肆走到洗剑池，实际使用普通攻击与武学打败两名道士；另外用测试存档抽查客栈、洗剑池、客房和大殿的渲染。定点测试存档不算人工走完对应主线。
- 浏览器截图与临时日志在 work/ 下，不发布。自动检查入口为 npm test，匿名资源为 npm run test:http，Cloudflare打包预检为 npm run deploy:check。

## 尚未达到的要求

本轮没有得到原游戏地图、脚本、完整台词、角色动作或音轨，不能给出可信的“原作匹配百分比”。现有剧情依据是攻略事件，部分护送、反复往返、可交换顺序的约会和后段切磋/败战仍由叙述压缩。75个地点不是75张独立原地图，洞穴、塔层、房间仍复用场景；角色动画、经济与隐藏分支数值也尚未校准。

这些是未完成项，不会因测试通过而消失。后续每补一段，应先记录来源与未知项，再检查前置条件、人物身份、物品取得/消耗及分支结果，把动作接入实际地图；真实界面重走相邻事件和失败重试，最后回归所有已实现结局与旧存档。只有这几项共同通过，才可把该段标为已验证。
