# R19：g24 十位旁观者浏览器验收

验收日期：2026-09-27。使用本地 `http://127.0.0.1:8787/`，独立有头 Chromium 会话 `observers-r19`，视口 1600 × 1000。未发布到云端，未读取原版游戏目录。

## 前置和范围

这是针对 `g24` 悲魔山庄决战的人工章节前置验收，不是从一级开始的自然通关。QA 文件为 `output/playwright/r19-observers-g24-qa.json`，使用当前存档结构生成，并经生产恢复函数校验后，通过游戏的“存入江湖 → 导入存档”界面载入。没有在浏览器中写入 engine、localStorage 或替换战斗结果。

- 当前任务 `g24`、地图 `m70`、阶段 `talk`；版本 3、剧情修订 19。
- 人物 64 级，气血 8500/8500，内力 5500/5500；药品各 99、银两 50000。这些是明确的人工 QA 数值，只为缩短本场操作，不证明自然难度平衡。
- 善线，`choices.g23=0`、`goodFirstZi=true`、`goodFirstMei=false`、`firstWoman='zi'`，`goodMedicineChallenged=true`；求医、重逢、辞别相关前置为已满足状态。
- `done` 和 `claimedRewards` 为空，没有伪造历史通关记录；入场脚点为 `(650,820)`，无战斗敌人、无进行中的演出。

依据 [求医与故人重逢参考合同](good-medicine-reunion-reference.md)，本场应将十名中性教众与纳兰潜凛这个战斗对象区分。网页的具体站位、人物图像、对白和 UI 是独立表现设计。本次不校验原版布局、原版动画或整条结局。

## 发现、修正和最终复验

首次入场发现左侧第五名旁观者与主角入场站位重叠，另有与本场无关的通用行脚商人位于中央。根代理将该观众移至 `(540,820)`，并仅在对应 `medicineCare/m70` 场景抑制商人。初次截图 `r19-observers-before.png` 和 `r19-observers-battle.png` 留作发现记录，不作为最终通过证据。

修正后，本会话先刷新页面，再经同一导入界面重新导入原 QA 文件，未沿用旧页内存中的场景。随后又发现战后站立人物与提前叙述倒地的旁白不一致；根代理改为实际倒地目标与后续人物演出。实际点击暴露出倒地人物统一禁交互的拦截，根代理为当前任务、当前地图、`after` 阶段的指定查看目标增加明确授权，其他倒地演员仍不可交互。

最终实测结果如下：

1. 入场可数出左右各五名、共十名旁观者。主角与第五名观众分开，中央商人消失；十人没有覆盖左侧任务面板、右上小地图或底部技能按钮。纳兰的任务标记清晰可见。
2. 鼠标点选纳兰人物，主角实际从入场点走近，打开正确的战前对话；两次点击“继续”后正常开战。
3. 战斗 UI 显示“应战 · 1名对手”。纳兰具有敌人血条；十名旁观者仍在场边，没有转成这场战斗的敌人。战斗和获胜截图中均未出现十人的敌人血条。
4. 最后一次从 QA 前置重打，使用正常 `J` 攻击按键实战约 12 秒，纳兰被击败，主角气血为 8190/8500。任务提示切换为“上前查看战后情况，陪真儿料理后事”，纳兰实际倒地，十名旁观者仍保留。通过游戏导出按钮保存 `r19-observers-g24-won-ui.json`；只读核验其 `phase=after`、战斗名册仅纳兰一人且 HP 为 0、`defeatedIds=[0]`、结果为 `victory`。
5. 倒地交互修复落盘后刷新，再由 UI 导入这个真实实战导出的获胜存档。点击“寻路前往”，主角走到 `(990,613)`；界面出现通用“继续前行。”，点击“继续”后实际进入 `g24_aftermath` 的“庄中后事”演出。
6. 真儿先出现在场中，随后实际走到倒地的纳兰旁并跪下，再出现她的首句对白。截图区分了入场位置与跪下位置。验收停在这段演出首句，没有继续安葬、离岛或整条善线结局，也没有据此宣称该章自然通关或完整复刻。
