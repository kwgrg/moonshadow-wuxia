# 善线塔内至落叶谷长夜：现状与空间审计

2026-09-24，受审基线 `36479ad`（revision 14）。范围为 `gTower1–8 → g19 → g20`，仅为说明分支出口而读取 `g21/gBad1`。本轮审计只读本项目代码、既有核验记录，并运行隔离的内存夹具；不访问原游戏目录，不修改浏览器存档，不把模拟当作自然通关。文档写作期间根任务开始生成新塔背景，以下“当前实现”均指基线，不能把新文件存在算作已接入。

## 结论

当前代码可以按“八次三敌战、塔顶选一次、谷院选一次”的规则推进，但救人现场、逆返塔层、见孟、安葬、入房与长夜分支均没有各自的操作状态。最明确的实际问题是塔顶直接通谷院、夜间跨房变白昼，以及四拒后亡者仍跟随。此前救紫轩和救眉儿的 R14 增量已经完成到塔入口，不应将这些旧后段缺口算作它已验证的范围。

## 隔离复现结果

这些是在内存中构造章节边界的代码检查，不是全流程自然档或浏览器验收。

1. **逐层强制战果**：依次置当前任务 gTower1 至 gTower7、目标图和善线合法前提，`routeTo(nextFloor)` 均为空，出口列表不含下一层；可退回已知下层和沙漠。进入战斗后由通用 `travelBlocked` 同时禁止退楼。待参考判定这是应保留的机制还是过度门控，不能在无证据时声称“原版也须逐层杀光”。
2. **塔顶瞬移式回谷**：g19 在 m69 调用 `beginObjective(); choose(1)`，得到 q=g20、partyNames=[蔷薇]、sequence=null，`routeTo('m51')` 实际返回 `[m69,m51]`。
3. **夜间跨房断裂**：同一 g20 状态含真实前段 care 完成旗标，在 m51 为 night 且有 shop；进入 r_leaf_hero_room / r_leaf_rose_room 为 day，无夜宿演员或夜宿目标；回 m51 又 night。不是“g20 院子总为白天”。
4. **死亡叙事之后仍同行**：以 g19 已带蔷薇的 g20 choice 状态连续四次拒绝，序列化/restore 后 q=gBad1、forsake=true、refusals=4，但 partyNames 与实际 companions 仍包含蔷薇。
5. **不误报旧档房门必锁**：两间卧房当前以早期 valleyCareStarted/valleyCarePrelude/valleyLegacyCare 开门；正常前段完成档可进入，低于 revision10 的后段档迁移会写 valleyLegacyCare。缺旗标的人工章节夹具会锁门，但本轮没有将其当作已证明的正常历史档软锁。新夜宿应有自己的入房授权，避免依赖无关旧标志。
6. **不误报邪线跳层串线**：m66/m69 的全局门户列表含另一分支候选边，不代表善线当前可走。普通善线逐层前进没有开启 m66→m69 或八开关；改造仍须测试这类分支隔离。

## 最小连续路线建议

### 塔内与返谷

- 保留 m62–m69 的稳定楼层身份，首先将真实楼梯入口/出口落在新图可行平台上。
- 楼层通行条件单独表达，不从“下一主线游标已到”推断物理楼梯是否存在；是否允许带余敌穿层必须依新参考决定，不能沿用地牢的特殊规则或强制全清两者之一来猜。
- g19 保留选择 ID。救人、选择结果动作、蔷薇交接普通跟随应有不同可恢复步骤。无论哪一个已确认选项，都应先执行现场动作，再提交明确救出状态；不得入图时提前陪跑。
- 回谷使用现有真实通路逆行：m69→m68→…→m62→r_good_desert→m54→r_good_feilong_approach→r_good_dunhuang_passage→r_good_dunhuang_approach→m49→m51。这个链是网页独立衔接，不是已逐图核准的原版地图。其顺序须由新参考确认必要中途事件，至少不能保留 m69↔m51 的一跳旧边。
- 回程不得重复重生当前章节已清敌军、重发奖、误触邪线开关或把蔷薇清掉。即使以后允许不杀尽过层，也应保存每层剩余军阵，而非把“曾进过地图”等同全清。

### 谷院、墓地与夜宿

- 谷院需要返谷现场状态与孟的生死交接，而不是让旧 g14 的重伤坐姿永久重现。现 g14 finalActors 仅 persistFor 到 g15，g20 并不会自动留一个孟演员；新段应按参考创建对应状态。
- 安葬应在真实墓位进行；建议独立 `r_leaf_memorial` 与谷院相连，名称、人物墓位数量及变更时点待参考。不得凭“安葬”自行补挖墓玩法、材料费用或原版未证的长段运尸路线。
- 已有 `r_leaf_hero_room` 和 `r_leaf_rose_room` 是两个独立房间，分别有院门，可继续使用。夜晚谈话放蔷薇房，主角回房/起身使用客房；是否每拒一次都实际出入、第四拒后的过夜/发现顺序由参考锁定。
- 两室可复用已目视的原创底图与现安全点：主角房床前 (620,450)、门内 (760,810)；蔷薇房人物 (950,550)、谈话点 (835,695)、门内 (750,815)。这些是网页脚点，不是原版坐标；新增床上动作须另外检查绘制锚点与脚底，不把床碰撞开放给行走。
- 用显式 lateValleyNight/lateValleyMorning 等阶段状态覆盖谷院、墓地和两房，演员演出中途刷新仍保持同一夜；拒绝计数不能共用无身份的泛化计数制造串线。
- 接受分支在确定毒情/次日出行后接 g21；拒绝分支在真实发现与安葬提交后接 gBad1。两个结果分别控制蔷薇生死与跟随，重复加载不复活、不重新加好感或奖励。
