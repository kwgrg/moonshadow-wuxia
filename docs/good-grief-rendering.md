# 复仇战结束后的敌人退场绘制

2026-09-27。本次只修正独立网页的渲染列表，不再读取原目录，不增加素材或原版内容。机制依据为 [已核参考合同](good-grief-reference.md)：摘星楼复仇战由纳兰死亡立即转入战后，其他守卫不要求全清。

## 问题与修正

主任务实际浏览器获胜时，纳兰已倒下，但42名未被击败的守卫仍停在画面中。引擎已结束战斗；渲染器却仍直接绘制 `state.enemies`，因此旧血条、未完成的蓄势提示以及小地图敌点也可能残留。重新读档会清空这份即时显示数组，却保留完整战斗凭据，所以问题主要出现在刚获胜的画面。

`public/renderer-v3.mjs` 新增只读 `visibleEnemies`，人物、血条对应的演员列表、标签密度、蓄势提示和小地图统一使用它。仅在以下条件同时成立时返回空显示列表：

- 当前任务规定以首领死亡结束，且玩家仍在该战斗地图的战后阶段。
- 主角存活且没有额外失败状态。
- 战斗进度已完成，当前记录结果为胜利，并通过生产引擎 `canCompleteCombat()` 对完整名册、击败身份及前置战斗的核验。

其他情况继续展示原来的敌阵。判断依据是持久战斗记录，不要求读档后的即时 `state.enemies` 仍有45项。

这只改变展示：没有删除持久45人名册、将存活守卫生命改成0、补写击败ID、发掉落或增加击杀数。下一幕的纳兰遗体与真儿由独立演出演员正常绘制。普通全清战、尚未获胜、失败或损坏记录不会因为一个 `after` 标签而被隐藏。已结束战斗的攻击输入和鼠标命中保护由其他运行时/界面修正负责，不以此渲染改动代替它们。

## 验证范围

`tests/validate-good-grief-rendering.mjs` 使用实际 `GameEngine` 和 `Renderer.draw()`，在记录绘图调用的画布接口上执行20例检查，已通过：

- 通过实际技能调用击败纳兰后仍有44守卫存活，立即不再绘制残敌实体、敌方血条、蓄势提示和小地图敌点。
- 反复绘制前后的完整状态相等；持久名册仍45人，仅纳兰有击败身份；读档后结果相同。
- 复仇战、天山普通战、善线普通首领战的活动阶段与未经证实的战后标签保留实体、血条和威胁提示。
- 缺少记录、未完成、仍为活动结果、失败、缺击败身份、缺军阵成员、错误任务记录、主角死亡、额外失败、阶段错误或首领仍存活等11类状态不能触发退场展示。
- 进入后续演出时，纳兰遗体与赶来的真儿仍然可见，主角不会被一同隐藏。

相关回归亦通过：`validate-interface.mjs` 覆盖243个当前场景、13类界面及2203次图片绘制调用；`validate-good-grief-staging.mjs` 继续通过14场演出、248次恢复（含20次移动中恢复）及墓标、门槛检查。差异格式检查通过。

这些是网页引擎和绘图调用检查，不能证明像素外观、原版实时表现或完整流程达标。实际浏览器再次获胜后的画面由主任务另外记录；本页不把画布接口测试冒称浏览器截图验证。
