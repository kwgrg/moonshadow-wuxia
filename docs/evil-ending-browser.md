2026-09-27。本轮原版目录未再次读取；只使用既有机制核验的原创概述，机制出处见 [参考记录](evil-ending-reference.md)。不复制原版图片、地图、音频、动画、脚本、配置、完整对白或解包文件。新增梦境、海岸、儿童、可容四张图使用内置 image_gen 纯文字独立生成，无任何输入图；交付文件、完整提示词、生成源与哈希见 [制作记录](evil-ending-art.md)。

## 实玩起点与方法

本机静态预览 `http://127.0.0.1:8787`，使用有界面的 Chromium 与游戏正常按钮、行走、对话、武学、存档导入/导出。只读取自动存档作证据，没有在控制台修改引擎、生命值、旗标或存储。原版游戏没有在本轮实机对照运行。

两支均从明确标注的章节 QA 档开始：`e13`，第八层，八锁已开，64级，生命2892、内力1310，低支网页倾向0、高支4。该档是为晚期章节准备的测试夹具，未包含从开头实际培养和前八层机关操作；不能把本轮当作默认等级、原版难度或全游戏连续通关。之后保存的检查点均来自界面的正常导出。

低支会话为 `evil-ending-r18`，主要 CSS 视口1280×720；镜头另在1024×768检查。高支实玩、两种实际梦战结果和证据见 [高支实测](evil-ending-high-browser.md)。

## 低支实际过程

1. 按地图指引从第八层实际经过第七、六层返回第五层。牢门关闭时真儿位于栏内，影枫停在门外；对话之后开门、接出，接已核的直接归庄。八个开关的此前取得是 QA 前置条件，不是本轮逐一实际打开。
2. 在卧房照料真儿、听铁云报告，然后正常行走到庄门，进入29人战。第一次未攻击而实际战败；刷新后仍显示失败与再战选项，没有越过剧情。点击“再战”后使用 J 与已装备武学、清心咒完成战斗。真实导出 `r18-family-gate-won.json` 为 `e14/after`，名册29、去重击败29、胜利，生命2751，金钱950，击杀29。
3. 战后沿实体路径回房，完成探望和三月过渡，再以真儿视角走入后花园。读信揭面中正常保存刷新，恢复当前对话段而不跳过认亲或直接交药。对话段可能从该段首句重放，这不等于逐字光标恢复。
4. 真儿回房送参汤，影枫服用后坐地、中毒提示出现；汤碗与桌子为独立绘制，未向背包添加药品。毒发处导出 `r18-family-poison-played.json` 并刷新，保留阶段与姿态；无结局选择按钮。
5. 完成胁迫对白后一次提交 `evilFinalOutcome: family`、`evilFinalModel: web-v1`、Mercy=true、Cruel=false。低支拒绝伤害、得解药、眉儿离去、五年过渡后到家庭海岸。儿童有独立小身形与头像，并从右侧走到父母中间。
6. 正常对白完成“忘忧余生”。实际导出 `r18-family-completed-played.json` 为 `e14_family/complete`、`ending: family`、金钱965、击杀29；刷新及再次通过UI导入后结果和奖励不变。`done` 只包含测试起点之后实际完成的8项，没有伪造前程历史。失功是叙事标记，未把保留的64级技能误称原版数值已清除。

上述导出文件位于被忽略的 `output/playwright/`，不进入产品或部署包。

## 浏览器发现、修正与目视复验

- **可容人物错用、头像越界。** 初次低支看到男性村民和空头像。为可容独立生成青绿侍女图并接入场上人物及头像；高支刷新后首次对白、揭面前后均已截图打开检查，见 `r18-high-kerong-first.png`、`r18-high-kerong-revealed.png`。
- **同地图入梦背景未加载。** 实际高支已换地点名并开四人战，却仍显示卧房。修正任务推进时的场景加载；图片未准备好会等待，独立梦图失败可重试且不能静默回退卧房。从再次正常走到的睡眠检查点刷新并自然推进，`r18-high-dream-prelude-fixed.png`、`r18-high-dream-four-fixed.png` 确认已显示新月夜院落，随后真实梦败出口仍有效。
- **坐姿、汤桌、儿童被对白挡住。** 本轮剧情镜头上移；较高比例允许镜头移入对白背后的暗色底边，不改变战斗相机。儿童最终走到父母之间。1280×720与1024×768两种CSS视口实际截图并打开目视，坐姿、汤桌及儿童全身可见。1024×768的对白上缘实测为498px，关键演出在其上方；该轮重载和导入未捕获页面脚本异常。没有推断所有手机与屏幕均已验收。
- **梦境读档与异常生命值。** 复核发现UI导入/手动读档未调用梦境结算，以及负生命值可冒充合法0生命瞬间。统一恢复入口，保存有效归档后再切场；只接受精确0的合法瞬间记录。运行时专项增加实际页面读档函数与损坏档覆盖，不把自动化结果冒称人工操作过每一种损坏档。

已目视的低支关键图：`r18-eight-locks.png`、`r18-direct-return-report.png`（实际是29敌开战场面）、`r18-zhen-perspective.png`、`r18-letter-reload.png`、`r18-poison-tall-fixed.png`、`r18-poison-wide-fixed.png`、`r18-family-child-fixed.png`、`r18-family-together.png`。旧遮挡截图保留为缺陷证据，不作为修复后画面。截图与QA导出都不随站点发布。
