2026-09-24，先对提交 b567253 运行完整自动回归与静态发布预检，再对实际浏览器发现的两项局部修复执行相关子集复验。这里只证明列出的网页实现合同；原作完整匹配度、全流程可玩性和画面质量不能由测试数量或模拟通关推定。此审计未访问原游戏目录，也没有读取或复制原资源。

## 已核机制、原创表现与未知

有界静态参考支持的顺序是：小筑醒来后返庄，右厢房争执并目送蔷薇离开，隔夜，铁云外出寻找后返回，真儿入场传讯并离开，影枫再决定赴摘星楼。原始证据的定位与限度见 [参考记录](hut-return-reference.md)。消息主题有攻略交叉支持，但本轮没有原版实机录像、逐句台词或精确动画核对。

网页将上述顺序独立实现为 e04_homecoming → e04_quarrel → e04_wait → e04_report；对白、三处房间布局、人物站位、步速、光照变化和可续存演出均为原创适配。四段没有新增战斗、死亡、婚约、好感、善恶、武学、钱物或治疗奖励。report 完成才清理旧同伴并提交 evilHutReportHeard；真儿不是赴楼同行者。

尚未确认原版行动间隙的输入行为、旅行失败、精确动作时间、真儿离场去处及抓捕现场。本轮没有补画主角未亲见的抓捕，也没有据蔷薇离家直接设置死亡。

## 专项实际覆盖

测试文件为 tests/validate-hut-return.mjs，调用真实 GameEngine、世界路线、演出和存档恢复；不是浏览器渲染或原游戏回放。

- 两种已挣得小筑答复分别合流返庄，前史选择、好感和资源不变。真实引擎行走经过 m16 → m17 → m49；进入右厢房，再经大厅、后园回主角房，翌日回大厅传讯，最后赴 m71。跨图必须经过当时可用的相邻出口，移动线段不穿碰撞。
- 每段必须满足自身前置与完整演出；未来旗标不提前提交。e05 同时要求“小筑夜已结束”和“传讯已听完”，各自可使用明确的旧档历史例外，不能只凭 visited 或游标跨越。
- 蔷薇先走离再隐藏，空房重访不复生；铁云外出、返回、告退之后才是真儿入场。真儿再走离并隐藏，同行列表为空，没有重复跟随人物或虚构尸体。
- 夜间坐下、黑场切晨、天亮起身与日光 cue 顺序一致。逐步、移动中、计时中和旅行中恢复保留位置、角色姿态、可见性、演出游标、资源和既有答复；不把读档当成任务已结束。
- 错分支、缺前置、错地图、其他任务 sequence 或投影场景混入的保存被拒绝为有效演出，不写未来 staged/done，也不发奖励。重复完成已完成四段不增加账本、钱物、经验或选择效果。
- e05 必败后原有三次拒绝致死合同保留，失败刷新仍为零生命和第三次拒绝；回到末次答复后接受不会重放本章收益。该段普通战斗失败/剧情失败的通用检查还由 recruitment 专项覆盖。

本次专项结果：2种前史、192次演出恢复（其中42次移动中、18次计时中）、20次旅行恢复、20个无效演出存档与483个旧档案例通过。数字描述测试范围，不是还原率。
