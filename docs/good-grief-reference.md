遵守 [AGENTS.md](../AGENTS.md)：原目录只读；必要条目只在命令进程内存中检查，使用已有通用 lzokay 依赖，没有建立原资源导入器。没有把原脚本、完整对白、NPC 配置、坐标、图像、音频、动画或解包副本保存到仓库、work、产品或部署资源。本文只保留独立概述及查找元数据。人物与场景的具体构图、对白、动作、参数和保存系统须独立制作。

## 已核验顺序与条件

1. **安葬蔷薇后先有天山封路战。** 落叶谷的 Event2100 出口加载天山及 `map032_1.npc`，统计 Kind1/Relation1 敌人，关闭三个出入口，随后启用 AI。配置有33名无忧教男弟子及1名领头，共34名敌人；全员绑定同一个天山死亡回调。死亡回调每次减计数，归零才重新开放出口、置2101。不能把安葬后直接去山庄见真儿当作这一段完成，也不能打倒领头一人即开门。
2. **到庄见真儿，告知死讯后才去寒波谷。** 2101山庄入口重新安置真儿并关闭三个出口；真儿交互说明蔷薇死讯、迟到的解药、其父追杀影枫等关系。真儿希望返回忘忧岛，影枫坚持复仇。她离庄后从场景移除，随后开放出庄口、置2102。这里没有新的选择菜单、没有真儿同行设置，也没有玩家领取或消耗背包解药。应让玩家看见她离开，不能又把她编入去小筑的队伍。
3. **小筑现场由真实到达触发。** 2102进入寒波谷，先移除活着的紫轩和月眉儿，加入她们的遗体及三名教徒遗体，再开放谷内9号触发。触发后影枫跑近现场，随后直接转到樱花谷安葬，生成两座墓，置2103。不能保留活着的二人交谈、让玩家救活她们，或把三具教徒遗体变成新战斗敌人。原版是谷内到达触发，独立网页可用明确的走近现场交互承接。
4. **安葬后实际出谷赴摘星楼。** 樱花谷2103出口返回寒波谷；谷外和倚天山连接口有对应2103分支。摘星楼入口读取 `map025_2.npc`，再运行复仇对峙。没有从两座墓直接加载摘星楼的调用，因此两地之间应保留可走路线。沿途已核有特定敌方配置引用，但本轮没有核齐全路军阵数量、重生及路径，不能宣称所有沿途敌人已恢复。
5. **末战是44名敌人与纳兰，纳兰倒下就启动收束。** 摘星楼配置为25名无忧教弟子、18名男弟子、1名教徒，均 Kind1/Relation1；另有1名 Kind1/Relation2 纳兰。对峙后明确将纳兰改为 Relation1、绑定专用死亡回调、启用 AI、置2104。楼中三个出口在战前关闭。此配置没有陪同真儿、紫轩或眉儿，也不是40多名旁观者。虽然入口取了敌方计数，但纳兰的2104死亡回调没有扣总数或检查清零，而是立即关闭 AI、清除人物、开始战后事件；不能把全清45名设为结束条件。
6. **真儿是在战后到场。** 纳兰倒下后，现场转为其遗体，加入真儿；她移动到父亲旁，影枫跟上，之后移除遗体、改变人物姿态并继续对话。最后叙述安葬与二人回忘忧岛，播放结尾片段、释放地图、回标题。该分支没有海岛 LoadMap，也没有跟随指令。网页可以把葬父、岛岸尾声做成独立可见段落，但必须标为原创展开，不能称原版还有一个可探索岛图或原生同行操作。

## 战败、重复触发与分支边界

- 已查天山2100入口、复仇对峙和2104纳兰死亡段没有把主角败北改成剧情胜利，没有失败后自动到下一阶段的指令。七个读取到的影枫模板均引用通用主角死亡，已知该回调返回标题。由此支持网页把两场战斗的主角倒下视为失败。**未进行原版实机失败、同帧双方倒下或脚本路径解析优先级测试**；网页原地重试、敌方快照与一次奖励账本属于独立适配。
- 天山34人全清和摘星楼纳兰死亡是两个不同完成条件。天山剩1人不能推进；摘星楼仍有守卫但纳兰倒下应进入收束。网页要明确处理主角已死时不能通过残留结算触发结局，并防止重新载入战斗刷新已领取掉落。
- 小筑9号触发一开始就关闭自身，安葬后推进2103；原版没有让用户反复发现并再次埋葬的奖励循环。墓对象的原配置复用了孟知秋墓定义，这只说明资源复用，不是墓碑文字、形状或人物身份的可靠依据。网页应使用自制两墓和清晰身份说明。
- 真儿离庄至纳兰败亡之间不在已查战斗配置中。不能将 R16 求医成功支线的四人团聚、首谈选择、最后招揽或同行名单带入本悲剧分支。`forsake` 是网页自己的分支标识，不是原脚本直接移植变量。
