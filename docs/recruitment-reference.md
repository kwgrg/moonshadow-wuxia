## g15：已证实的完整关系

1. **招揽**：摘星楼交涉，最多三次。拒绝路线走留楼、破围、地下救紫轩，继而送她回芭蕉小筑；该路线应继续 `g16` 等既有正线事件。
2. **接受与攻武当**：接受后载入武当山顶的专用敌我配置。敌对方包含天星道长、张惟宜与武当弟子；友方包含纳兰潜凛及无忧教徒。所有目标清除后才触发返回摘星楼，不是接受后直接播放孤独结局。
3. **授职与下地牢**：回到摘星楼受任护法左使，随后转往地下。网页 `m61` 与 `m71` 均是现有任务层对同一摘星楼区域的近似映射，不能以这两个网页 ID 证明原版空间结构。
4. **固定处决**：蔷薇在前、紫轩在后。本地续段没有任何 `Choose`；两处均安排杨影枫攻击受害者，清空其普通死亡回调，再继续演出。这里不能借用 `e06` 的“拒杀则蔷薇自尽”，也不能给紫轩凭空增加反击单挑或获救支路。
5. **离别**：回到楼内见真儿；真儿返回忘忧岛，月眉儿也离开。人物离去及生死状态必须持续保存，不能继续以四人同伴状态游玩。
6. **结局收尾**：纳兰后来练功死亡、影枫继位并习成武道德经、最终孤独，属于该路线的时间推进与结局内容。查到的武当完成回调最终播放结局并返回标题，没有新增武道德经物品或可装备技能的发放调用。当前证据不支持另造“去禁地取经”的可玩支线；精确取书或修炼交互也没有证据。

第 4 点的无选择结论及转场次序由本地静态直接支持；第 6 点的后期人生概述同时依赖详攻略/NBE，不把攻略尾部的传闻式死因当作额外游戏终局。

## e05/e07：实现契约及保留的不确定性

`public/recruitment-revisions.mjs` 已提供两项独立数据：`battleBeforeChoice`、`scriptedLoss`、`forcedOutcome:'defeat'`，以及逐事件的 `refusalRule`。战前对白不再声称已经落败；拒绝临时对白、最后机会警告、致死对白与接受后续分开。

- `e05`：`limit:3`、`outcome:'fatal'`、`key:'e05'`、`refuseIndex:1`。
- `e07`：`limit:2`、`outcome:'fatal'`、`key:'e07'`、`refuseIndex:1`。
- 第 N 次拒绝必须先保存计数，再决定重开菜单或失败。只有接受才播放公共 `after`、完成任务并发后续奖励；最终拒绝不得领玉佩/遗书、生成同伴或移到下一任务。
- `lastRefusalAfter` 是达到 `limit-1` 后、最后一轮答复之前的警告，不是最终死亡对白。`fatalAfter` 只在达到 `limit` 后播放。
- 剧情败战后再读档不应重打一场，也不能使原本致死拒绝变成普通掉血重试。持久化失败与回到答复前的网页适配必须各自有明确状态。

原版邪恶值并非详攻略表格的 ±1：本地 e05 败北回调重新建立 100 的基线，再按答复推进增减；e07 也操作同一隐藏值。网页已有前段累加的 `evil` 及结局阈值，不能只把某一处原数字搬过来。本轮保持原选项 `effects:{}`，**接受早晚影响隐藏邪恶值这一点尚未整体校准和实现**。原版 e07 中还见到未带 `$` 前缀的增值参数，其解释需核对原引擎行为，不能只读一行就断言实际增加。

两半玉佩、遗书原本是谁持有、何时转移到主角包裹，不能仅从月眉儿能开门推出；网页当前物品奖励仍需独立账本核验。邪线摘星楼到海岛、村中追踪假真儿、离岛前神驼帮清场也未因招揽选择可用而自动成为完整动作链。
