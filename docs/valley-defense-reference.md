# 禁地遭俘、山庄清场与落叶谷传功：有界核验

核验日期：2026-09-23。原目录仅只读参考；本轮没有读取原美术、音频或动画，也没有保存原脚本、配置、完整对白、解包副本或导入程序。必要的选定条目只在内存中解码，持久记录限于下述原创概述与定位元数据。先按事件号和被引用的文件名定位，再查直接相关入口、NPC 配置及回调；不是原版实机录像核验。

## 结论与现有误差

- 清场发生在**悲魔山庄**，并非落叶谷：丁戈交涉后，48 名无忧教男弟子、6 名霹雳堂弟子与丁戈本人共 55 敌全部清除才重新开出口。阵容没有友军，不应添加保护铁云或孟知秋的失败条件。
- 落叶谷在主角抵达时已经被毁，当前直接入口加载的 NPC 只有重伤孟知秋。没有本段的清谷战初始化；不能为补足玩法凭空再加一战。
- 传功原生增益明确为一次 `AddExp(100000)`。直接分支内没有授技能、加最大内力或加攻击属性的调用。经验增长应实际进入本项目成长系统，并由领取账本保证一次。
- **本段传功后孟知秋仍活着**，Event2001、Event2002 均有继续交谈分支。其脚本文件名虽然带“临终”，且对白表达伤重与后事担忧，也不能将此处实现为立即死亡、尸体或隐藏。后续 Event2021 的死亡状态超出本次实现窗口。
- 俘获后的返程先在中原码头遇铁云，得知山庄被占，随后清庄；铁云报告不在落叶谷或清庄之后。
- 传功离谷后先经过寒波谷，再到芭蕉小筑发现紫轩不在，决定先赴摘星楼救被掳者。原map019把小筑触发区与谷地合在同图；网页拆成可步行往返的谷路与既有小筑室内。决定救人时设置摘星楼入口所需的 Event2003。
- `g13` 当前 4 敌加结尾叙述还压缩了两轮战斗与中间找到姐妹的动作。本轮记录此缺口，未将它偷换成山庄或清谷的额外战斗。

现有合并数据中，`g13` 是 m60 普通 4 敌战，战后文字一次讲完找到姐妹与三女遭俘；`g14` 是 m51 talk，默认领取 65 经验、15 银两，并在前情声称已由铁云报告和清庄，实际没有清庄阵容或传功动作。`g15` 已有三次拒绝、正转邪后续与稳定选择 ID，本轮仅应增加其前置，不能回退这些已完成机制。

旧 `docs/fullflow-completion.md`、`docs/late-story-audit.md` 的“临终传功”和“独立内力转移”措辞是先前待核描述；以本次原生调用与事件状态作为修正依据，不能沿旧词补未证实数值。

## 旧存档与分支边界

- 未完成旧 g14 的存档应转入新码头报告段，再逐步清庄，保留用户此前钱物与等级；旧前情“已经清庄”不构成新战斗完成证据。
- 已完成旧 g14 / 已在 g15 或更后方者保持历史进度；可使用 `valleyDefenseLegacy` 通行例外。它只说明旧版已越过该段，不能替代 `staged_...` 或宣称完成新55敌战与传功演出。
- 旧 g14 原先仅给默认经验/银两者不自动补发100000，也不强迫重打；若需要体验新流程应由新游戏或明确的重玩机制进入，不能用迁移悄悄重复结算。
- 新版必须通过 `valleyManorReported → manorInvadersCleared → valleyPowerReceived → valleyHanboReached → valleyRescueResolved` 依次开通；visited、数字游标前移、旧地理捷径不能单独当作胜利证据。
- 上述链属于未转入 cultPath 的善线。早期邪线的孟知秋传授/攻谷、原 Event818、Event3000 与被毁谷后其他结局各有条件，不复用此55人战或本段经验奖励。若页面共用地图，演出、战斗阵容、封路和毁坏外观都须限定对应窗口，早期访问与邪线不能被善线门槛锁死。

## 仍未证实与验收要求

本次没有原版运行画面，没有测原敌 AI、精确攻击时机、玩家操作手感、角色动画、原地图碰撞与视角遮挡，也没有确认原内功成长曲线。g13 第一次战败钩子的解析缺口与中间室内全流程仍保留。传功后孟知秋最终何时死亡及后续回谷细节不在本轮实现中。

专项应验证55敌全清、漏1敌不放行、无友军失败门槛、重载剩余敌HP/清除身份、失败后拒绝行动与无奖、重试不刷成长、传功前后逐步读档与经验一次结算、门控无法绕过、善邪隔离，以及旧已过档不发新奖励。实际浏览器还需检查开场不会无输入即死、人物不重叠、重伤老人不变成尸体、传功反馈可见、毁谷与寒波谷足点对应实图。测试通过仅证明这些契约，不代表全流程复刻完成。

成长边界：专项复现了原网页 gainExp 可升过99而读档压回99的经验丢失。根任务将成长与恢复统一为99级上限，满级保留剩余经验，经验存储上限999999；接近上限则饱和。此为独立网页成长约束，不冒认原版等级曲线。
