# 海屋疗伤演出事务验收

更新日期：2026-09-22。对象为网页版正线 g08_deliver 的独立演出；仅使用现有项目剧情核验概述，不访问、复制原版内容。

## 事实、原创设计与未确认项

- 已有攻略审计支持：离忧山采十二株银丝草，带回海边小屋煎药，月眉儿好转，随后两半玉佩相合，再赴禁地密室。
- 本项目原创实现：m33 海屋中的人物站位、走位、交药动作、煎药/服药/恢复/玉佩效果与时长。m33 来自既有网页治疗场景的复用，不代表已经证明原版地图编号、床位或室内布局一致。
- 未确认：原版精确镜头、对白、等待时长、动画帧和每个演员的移动路径。本轮测试不能证明上述一致，也不能据测试数量宣称全流程复刻完成。

## 事务契约

1. 未持有十二株银丝草时，自动触发、手动开始、交互和主线开始都不得启动疗伤演出或展示成功对白。
2. `handover` 步骤实际消耗十二株，并把数量写入 `s.stagedHandovers.g08_deliver`；库存扣除、账本更新和推进到下一步在一次同步操作中完成，之后才保存。
3. `sequence.handoverItems` 是当前任务账本的投影。恢复时以持久账本重建，不能因瞬态 sequence 清空而再次扣药。
4. 交药后即使库存只剩零株或两株，仍能完成后续煎药、服药、恢复和玉佩对合；requiredItems/consumeItems 按已交数量抵扣。
5. 演出释放之前不得完成任务、离开地图或用旅行按钮绕过；演出全部完成后才获得两半玉佩，且只领取一次。
6. 存档恢复保留当前步骤、演员状态、演出 cues、等待进度与交药账本。交药前后、等待途中及效果展示期间刷新，都不得重新付药或免费领药。
7. 旧版 v2 只依据已完成 g08 的记录迁移既成的返屋事件；现代 v3 缺药档、未完成 g08 的旧档不能免费补齐物品或完成状态。

## 验收设计

`tests/validate-treatment-staging.mjs` 已加入 npm test，设计覆盖：

- 初始十四株：交药前库存十四/已交零，交药后库存二/已交十二，全程总数守恒；任务完成不新增经验或银钱。
- 每个演出步骤保存并单独恢复直到完成，额外覆盖等待中间和已设置 cues；恢复前后步骤与表现状态相同。
- 删除快照中的瞬态 handoverItems 投影而保留权威账本，仍能恢复并完成，验证投影不是消费依据。
- 十一株在自动/手动/交互/主线入口被阻断；海屋外不能直接完成或开始交付。
- 交药前后都尝试出图、旅行、移动和直接完成，验证不能绕过演出。
- 已交付后读档、重入或重复触发不再扣药、不再给玉佩。
- 旧 v2 迁移幂等，现代 v3 无免费补药，正常邪线推进不会进入此正线演出。

既有 `tests/validate-errands.mjs` 的交互帮助函数同步执行完整演出，原有护送、采集、缺物、准确扣除、玉佩开门和旧档断言保留。

## 执行状态

专项测试已执行通过：29 个演出步骤、34 份步骤边界及等待中间快照分别恢复至结束；全部保留十四株总量，其中十二株只交付一次，最后剩两株并只获两半玉佩。再次执行已经付款的 handover 步骤不重扣；删除瞬态投影后可由权威账本恢复。

既有 errands 回归也已通过。为了核验真实表现语义，治疗结束后断言真儿的跟随状态存在、海屋里固定演员与跟随角色合计恰为一人，并实际步行到密室：交谈时主线真儿与跟随者合计恰为一人，开始搜索后恢复通常跟随；没有取消同行要求。

这些自动检查尚不能证明药炉、药碗、玉佩、病者起坐和人物落脚正确。独立浏览器验收由场景代理进行：十四株开场、交药后刷新、每个关键表现状态、两株余药和两半玉佩、离屋随行，以及十一株负例。最终浏览器证据须另行记录，不能用上述模拟替代。

本轮真实治疗画面、交药后刷新、进出海屋和11株负例已经补验，范围及截图见 [治疗演出记录](treatment-staging.md)。招揽结果对白未结束时就保存死亡、死亡期间两类药不消耗已另加回归；界面专项现16项。
