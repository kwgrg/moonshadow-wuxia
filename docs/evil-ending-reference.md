## 当前产品差距

实际导入当前 `public/campaign.mjs` 后，`e13` 是八个开关旗标齐全后于 `m66` 救出真儿的交互；`e14` 是 `m49` 普通四敌战，`ending:true`。其战后只有数月相伴、书信诱导、真话药实为毒药及杀真儿胁迫的简述，然后 `chooseEnding` 以网页 `flags.evil >= 3` 直接选择 `alone`，否则 `family`。

当前普通战斗已经要求有效胜利进度，不能因历史审计发现过裸 `after` 结局就把那个已修问题继续列作现存缺陷。仍未实现的是 29 人实际庄门战、战后探视、三个月过渡、真儿视角的伪装揭露/读信/受骗、参汤中毒、自动分支动作、高支两次杀人及安葬/梦战/父墓，和低支解药/失功/五年后海边一家三人的可见结尾。

当前 `e14.after` 没有“眉儿忘带解药”的句子；历史对话摘要的该说法不能当作当前产品事实。原高支有给解药后再发生第二次杀人的依据，见下文。

## 静态已核的事件顺序

1. **塔中解救直接回庄。** 已找到真儿且八个塔内锁条件成立后，入口处理石门、主角走近与交谈，随后恢复生命、内力、体力，并直接加载悲魔山庄。真儿被加入为躺卧表示，铁云走近报告，最后设置庄门战触发区、关闭普通出入口。不是从塔顶任意走到庄门，也不能用一句“路上慢慢说”代替归庄照料与报告。八锁具体操作、塔内路线和此前找人条件不是本轮重核范围。
2. **玩家到庄门触发，29 敌全清。** 战前主角接近来客，依据隐藏值有两种交涉措辞，随后四位家丁被明确设置为 `Kind5`，初始化敌数，封触发出口并开启 AI，进入 `Event3210`。配置有 29 名敌对人物，每名均绑定同一死亡计数回调。每次减一，归零才转战后照料，不能只击败某个领头人或打四人就结束。
3. **战后先见真儿，再跨三个月。** 全清后主角恢复三值、停止战斗状态，走近真儿并交谈，接着由独立动作资源表现二人相伴。之后对白索引 `101020` 明确为三个月过去。网页可以独立表现拥抱、休养与时间转场，不能拷贝动作资源或把未播放的动画细节当作已核。
4. **药局先从真儿视角发生。** 随后加载新的庄内配置，主角与真儿的角色类别交换，以真儿为该段行动视角；侍女可容走来，执行易容揭露动作，之后转向月眉儿。眉儿让真儿先看书信，真儿随后认姐妹关系；再以影枫恶行为由诱导她试药。眉儿宣称药只会令服用者说真话，真儿最终答应。这里不是影枫本人主动选择喝毒药，也不是玩家可自由选杀与不杀的当前菜单。
5. **参汤、发作、胁迫。** 视角归回影枫，真儿走近并执行端汤动作，场上加入参汤物件；对白明确是真儿煮的参汤。影枫服用后显示中毒状态，眉儿出现，说明实际为断肠散，提出杀死真儿才给解药。没有查到这一过程向玩家背包发放/扣除药品、信件或解药的调用。
6. **此处由既有倾向自动分支。** 胁迫交谈后直接检查隐藏变量，进入两支之一；本回调没有 `Choose/Select` 菜单调用。数字对白库虽然另含看似选择标签的记录，但并未由这段调用，不能凭库里存在标签擅自加最终选项。

## 两种尾声

### 低倾向：拒绝伤害、解药与五年后

主角拒绝以真儿性命换取自己安全，真儿转而求眉儿救主角。眉儿动摇，给出解药并说明主角虽可活命却会失去武功，随后亲自离开。她在这个分支没有被删除为尸体，也没有明确死亡指令。离去前有淡出、攻击音效和对白，但未播放资源，不能仅凭音效补成自杀、自毁容或某个具体受伤动作。

本支接结尾片段后明确提示五年过去，再加载海边：影枫与真儿交谈，孩童走近，数字对白将其称为杨纳康，并明确父母关系。孩子使用的配置原名属于资源复用元数据，不能让网页最终显示成该配置原来的居民名。对白再次谈及影枫已失去武功。此分支未查到清空武学、降低等级或改攻击属性的调用，因此“以后不能战斗”的网页数值若需要实现，应独立设计，不能伪称复制了已核数值操作。

### 高倾向：两次杀人、安葬、四人梦战与祭父

1. 主角向真儿出手；淡出后删除其人物表示并加入尸体物件。
2. 主角向眉儿索取解药。对白索引 `101730` 明确她交出解药；之后主角被恢复为普通人物资源表示。没有“忘带解药”或“主角因此立即毒死”的已核依据。
3. 后续对话后主角再向眉儿攻击，删除其人物表示并加入尸体物件。两次出手都是受控剧情动作，不是可反复刷掉落的普通单挑。
4. 主角在真儿遗体旁有动作与反应，之后场景加入两座墓物并有安葬后的追悔交谈。两座墓复用同一个原物件文件；这不能解释成蔷薇在此被埋两次。网页应独立制作与本段两名死者对应的墓前表现，不能复制原物件或墓位。
5. 接着回到庄内夜间卧室状态，再切入梦境配置。真儿、眉儿、蔷薇、紫轩四个人物出现并质问主角，随后开启实际战斗，进入 `Event3220`。四人均为敌对并绑同一计数回调。梦境不表示现实人物复活，也不能给现实再次击杀四人的剧情记录。
6. **梦战胜败都能收束到父墓。** 四敌全清走 `AllDead1`，加载凌绝峰顶、恢复主角三值、父墓反思后播放结尾并回标题。同时本梦给主角明确绑定庄内的 `杨影枫死亡.txt`；该回调同样加载凌绝峰顶、恢复三值、父墓反思后结尾并回标题。因此不能强制梦战失败后“必须重试赢四人才能看尾声”。两条入口的原具体对白不复制，网页可用自己的文本表达梦醒与追悔。

这一梦中死亡回调是本段专门确认的合同，不能推导为庄门战或所有山庄战败都算完成；庄门战主角的当前死亡绑定来源尚未充分定位。此前资料把 `709448b9` 笼统归为普通失败回标题，不足以描述本梦中“梦醒祭父再结束”的事实。

## 倾向阈值与不可直接搬用的计分

原结局检查位于 `c06d41f2` 第 211 行：变量 `EvilValue`、字面比较符 `>>`、常数 `118`，命中后进入高倾向分支。此处可以确认是既有隐藏值控制的自动分支；**专用比较符在原解释器中的严格/包含边界，本轮未核**，不能未经验证改写为标准语言的 `>118` 或 `>=118` 并宣称精确一致。

庄门开战交涉另有 `<<112` 检查，仅决定战前措辞；不能把它误当作最终结局阈值。

原前段存在把此值设为 `100` 的入口与多个 `±5/±10/+15` 写入，而当前网页从 `0` 起使用自己的小权重。并且所查接受招揽的一条增值命令未写通常的变量前缀，其原解释器实际效果尚未确认。因此只把网页的 `3` 替换成 `118` 会破坏现有分支，不能解决原模型对应问题。后续应单独核定完整原变量合同，或明确保存一个有版本的网页倾向模型，并据已经提交的历史决策恢复；不能从总值凭空猜回某次未知选择。

## 独立实现及验收建议

后续实现应把原自动结果保存为独立、一次提交的结局决定，在胁迫演出之后使用；拆任务不应重复改变善恶值或领取原 `e14` 奖励。场景、人物动作、读信表现、药碗与墓物全部使用项目独立资源。照料、药局、梦境应有独立镜头/状态，梦境战果不得修改现实人物生死或给出重复普通击杀奖励。

需要覆盖：庄门残敌/失败/重试/刷新不能进入三月后；29个敌人身份与一次收益保持；毒药演出中不能提前终局；已提交分支刷新不可改向；两次剧情死亡与墓前只提交一次；梦战失败/胜利都到父墓而不串到家庭尾声；低支不出现尸体或梦敌；五年后孩子称谓正确；旧 `e14` 战斗中、已胜未结束、已结束以及缺失历史决策各自迁移，不伪造此前选择、不重领任务奖。实际浏览器必须走两尾声，尤其核验梦战自然失败和恢复。

仍未确认：原解释器 `>>/<<` 严格边界、完整隐藏值的实际生效路径、末次庄门战主角死亡绑定、原动画完整动作、药局期间可否自由操纵真儿、原敌方 AI/伤害与掉落、塔至庄自动转场在其他版本的差异、全程原存档。不能以29敌/4梦敌、事件数或模块测试通过宣布全流程完整复刻。
