# R19 道路遭遇：实现合同与验证边界

本轮不读取或复制原游戏文件；依据已保存的 good-medicine-reunion-reference.md 原创概述。程序、数值、对白与场景分别独立实现。

## 已核验机制与未确认事项

- 12 / 25 名敌对教徒是天明辞行后赴寒波谷与携人返庄初段的两份配置，不是求医守军，也不是整条路线的敌人总数。
- 药王谷外围 30 只敌对苍鹰；诊查没有全清要求。
- 这些道路没有清敌计数门槛。敌人存在不能变成新的任务完成条件。
- 原版敌人复生、精确 AI、伤势保存、奖励数值与同伴伤亡细义未由本轮核验。网页采取局部警戒、脱离后退回、跨离返保留敌人伤势、一名敌人一份奖励、当前地图明确重试，均为原创适配。
- 同伴继续非战斗跟随；不新增攻击 AI、可受击生命或护送失败，不宣称此处关系已完整复刻。

## 独立状态合同

- road-encounters.mjs 声明固定的地图、任务范围、67 个稳定人物 ID 和原创战斗数值；world 仅提供 scene.ambient 的 positions / heroStart，不决定奖励或主线完成。
- road-encounter-runtime.mjs 使用 s.roadEncounters[mapId] 保存固定名册、伤势、位置、攻击冷却、蓄势、失败及重试次数。s.roadClaims 是跨重试的逐人收据。
- 范围严格限定善线非放弃、非入教：g21 / r_good_medicine_edge；g23 与 g23_reunion / 两段教徒道路。m23 诊院及其他剧情不生成道路敌人。
- phase 保持原任务的 travel；不填 combatProgress、skirmish、done 或 claimedRewards。全清没有额外任务奖励或补药，也不会推进任务。
- 离图前与保存时保留活跃名册，返图重新绑定同一银行。敌人受伤、死亡与收据不会因跨图或刷新丢失；另一个地图的银行不会被当前重试覆盖。
- 主角死亡保持失败；手动导入、启动恢复、关闭面板均不得自动复活。明确重试恢复主角和当前地图名册，已付收据仍有效。破损名册需要显式重试，并保守停止此地图后续击杀奖励以防丢失的付款证据造成重领。
- 已有银行但 roadClaims 缺失、不是数组、含未知/非字符串/重复收据时，不重置名册、伤势、失败或 attempt，只将已有银行 rewardBlocked 置为 true。该保护跨刷新与重试保留；正常空收据和 <=18 无银行旧档首次进路仍能正常获得奖励。
- R18 数字任务索引用冻结的 REVISION_EIGHTEEN_QUEST_IDS 解释；旧诊院存档保持原地图、位置、资源，不补造路途与击杀历史。
