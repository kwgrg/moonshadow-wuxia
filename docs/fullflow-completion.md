- **既有攻略审计支持**：来自 [前期审计](story-audit.md)、[后期审计](late-story-audit.md) 及任务中的 `source/sources`。这里只使用当前文件中的核验结果，没有重新浏览来源页面；不能把原先的概述扩成未经记录的细节。

## 真正全流程完成的逐项门槛

所有下面条目都需要可检查的记录，而非一句“测试通过”。

- [ ] **事件覆盖**：共同路线、正线、邪线、正转邪、各已证实终局和支线有明确的前置→动作→后置关系；当前表中的必要动作不再只写在 narration 内。
- [ ] **信息时序**：人物身份、书名、死亡、背叛和战果只在玩家确实经历相应事件后揭露；跳过/拒绝/接受/先后不同均各自合理。
- [ ] **物品与经济**：全程道具/金钱/技能账本可追踪，交付和费用一次性，缺物/缺钱有可恢复行为；授技时点与可用技能一致。
- [ ] **地图与往返**：每一条必要路径、分岔、支线首次入口和返程可走；进/出口落点、剧情锁和主线追踪一致，不用任意传送替代被要求的路程。
- [ ] **护送与人物状态**：同伴出现、分离、受伤、被俘、死亡和换主控均持续保存；过图后不消失、不多出分身、不把同伴当敌人。
- [ ] **演出与操作**：移动、转向、靠近、跪拜/起身、受困/解困、跳墙/坠崖、开门/退场等必要动作可见；锁定控制和恢复控制都有边界，中断读档不会软锁。
- [ ] **失败与重试**：普通死、剧情败北、超时、错机关、拒绝致命分支分开验证；失败后不冒领奖励、不静默换路线、不重复释放旧人物。
- [ ] **隐藏分支**：列出每个计数/阈值的来源或适配声明，正邪分歧、四拒、双杆、谈话顺序和终局都测边界；只测“高/低两个结果”不足以校准原规则。
- [ ] **旧存档**：以 questId 与细阶段迁移，关键演出中、战前/战中/战后、物品已交、部分目标已做、远处返程、旧wave与旧数字索引均可继续；不要让新增任务移位换掉玩家剧情。
- [ ] **实际浏览器全程**：每条结构不同的主线必须从自然可达的前置状态连续走到后置；按真实鼠标/键盘/触屏交互，并覆盖各重要失败与回程。定点存档可作局部调试，但需明确与连续主线实测分开。
