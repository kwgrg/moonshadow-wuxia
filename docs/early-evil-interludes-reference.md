本文的“已核”是局部静态控制流与动作调用；不等于原版实机输入、碰撞、动画、数值或自由控制验证。本轮未重新浏览公开攻略，既有 [邪线衔接记录](evil-dungeon-reference.md)、[追踪记录](forbidden-pursuit-reference.md) 与 [后续渡口记录](evil-docks-reference.md) 只作为已有背景。两个数字对白索引包项尝试读取未完成，未将此尝试当成主题核验成功；下述梦境结论来自已解码的限定事件调用，不声称已确认完整对白寓意。

## 结论与当前产品缺口

1. **原谅和拒绝都进入梦境，而且是不同梦境。** 原谅进入 `Dream1`，人物为影枫、紫轩、纳兰真；拒绝进入 `Dream2`，第三人为卓非凡。两支都使用樱花谷情境，最后共同回到寒波谷醒来。不能把“原谅后梦境”理解成拒绝就无梦，也不能套用之后地牢选择产生的蔷薇婚礼梦/天池梦。
2. **第一次楼战没有在这个事件块中判定胜负。** 海边切镜先隐藏影枫和真儿，临时以纳兰为受控视点，教徒报告、纳兰靠近、与孟交谈，随后启用 NPC 行为并短暂等待，直接切回海边。所查段没有等待死亡、战果条件或纳兰倒地调用。
3. **两次楼战有不同触发和返回地点。** 第一次发生于送真儿回岛后的海边，返回海边并进入睡醒/失踪衔接；第二次位于密室招揽接受后返回村落的路上，返回山路。不能把后段孟胜、纳兰倒下的结果提前给第一次。

当前 `public/fullflow-revisions.mjs` 的 `e04` 只有战后选择及“留宿、翌日返回”的摘要，没有梦境演出或独占分支旗标。`public/evil-dungeon-staging.mjs` 的 `e06_rest` 只有坐下、休息、真儿离去、醒来，未切向楼内。`public/evil-docks-staging.mjs` 的 `e08_interlude` 已实现的是第二次交锋，包含纳兰倒下；它不能作为第一次的事件数据直接复用。

## e04 两支的已核动作

共同前提沿用此前核验：战前已经认出紫轩，单挑结束后才出现原谅选择。本轮从败后 Event595 检查梦境路由。

| 阶段 | 原谅支路 | 拒绝支路 |
| --- | --- | --- |
| 战后答复 | 菜单的原谅答复落入第一段；先有较长的双方移动、对话，之后紫轩被移除，影枫在场内走动。 | 菜单结果值 1 转入 `UnZX`；对话后紫轩向外走并被移除，影枫有后续反应。原版变量不应直接当成其他网页选择的通用索引。 |
| 进入梦境 | 明确跳往 `Dream1`。淡出，保存现实 NPC/对象状态，加载樱花谷、坐着的紫轩，影枫靠近。 | 明确跳往 `Dream2`。同样以樱花谷与坐着的紫轩开始，影枫靠近。 |
| 第三人出现 | 纳兰真被加入并走近；影枫转向她。之后真儿移动、被移除，影枫跑向她刚才所到的位置。 | 卓非凡被加入并走近；紫轩转向卓，随后也移动到他附近。 |
| 收束动作 | 真儿先消失；影枫奔走、反应，之后紫轩也被移除；影枫继续在梦中奔走。 | 影枫跑近并执行朝卓当时所在坐标的攻击动作；短暂等待后跳往共同醒来段。没有查到该段判定击杀、玩家输赢或战利品的分支。 |
| 返回现实 | 两支都明确跳往 `Next`，加载寒波谷现实 NPC/对象，移除紫轩、恢复较亮光色，影枫醒来并进入 Event600 与返庄引导。 | 同左；拒绝支路不会再进入原谅梦。 |

可以独立表现为两种受控梦境，但不能把“影枫攻击卓所在位置”扩大为“已证实卓被杀”；同样，梦中人物被移除不等于现实人物死亡。紫轩使用的特殊动作仅确认发生及其前后位置关系，本轮未播放资源，不能认证具体拥抱、起身或其他精确动画。对白中嫉妒、追悔、承诺等具体寓意未由本轮成功核对，不应由演员组合自行推断成原作事实。

两段有脚本驱动的移动、镜头和动作；本轮未验证玩家在等待间隙是否能自由输入。适合网页独立受控演出，不应宣称已核为可自由战斗的梦境。未在这些事件段发现物品、经验、金钱、武学或恢复属性的发放调用。

## e06 首次楼战与返回海边

Event3020 的顺序为：船渡到岛码头 → 海边交谈/休息衔接 → 首次摘星楼切镜 → 返回海边 → 海边直接回调 → 真儿外观身影离去与 Event3030 追踪。

首次切镜的静态次序：

1. 海边对白之后淡出，加载摘星楼及 `map025_MZQ_VS_NNQL.npc`，先关闭 NPC 行为。
2. 隐藏影枫和纳兰真；将纳兰设为临时受控角色并更新视点。这里不是影枫本人回到楼内。
3. 无忧教徒向纳兰走近并报告，纳兰移动；继续交談和镜头调度。
4. 恢复影枫/真儿/纳兰的角色类别，启用 NPC 行为，等待 3000 毫秒。
5. **无条件淡出返回海边。** 这一块未检查任一角色生命、未等待击败或死亡回调，也未切换纳兰倒地状态。该等待值只是定位元数据，网页无需照搬时长或由它推断原战斗精确结果。
6. 返回海边后先显示影枫、保持真儿隐藏，恢复影枫视点与行为；随后运行海边直接回调。回调先处理影枫特殊动作与对白，再将真儿外观演员设到离去位置、显示并移动；之后处理影枫醒来动作、置 Event3030，最后删除真儿外观演员。

因此新实现不应在返回镜头的第一帧就永久删除真儿，也不应把她保持为月眉儿正式同伴。网页可独立重写“短暂隐藏 → 离去动作 → 主角醒后寻找”的表现，并依已实现的追踪段继续。当时仍使用纳兰真的外观和称呼，真实身份与替换起点不在本轮新增认定。

海边特殊动作未实机播放。不能单凭动作资源编号补一个明确的刺杀犹豫现场。首次楼战也不能因后来的第二次战果而提前记录 `NalanDead`、授予经验、掉落、恢复或改变主角现实生命；本事件段没有这些奖励依据。楼内战斗配置本轮未读取，敌我精确阵容、属性、AI 以及 3 秒间实际伤害仍未确认。

## 实施前后须验证的项目

- 两个 e04 结果确实只播放对应第三人；拒绝梦不能落入原谅梦。双 true、全 false、路线错误及缺离去前置不能恢复或启动梦。
- 小筑战败、重试、选择后刷新不会提前做梦或再次加善恶；醒来只完成一次，返回后紫轩现实已离去。
- 梦中真儿/紫轩移除与影枫攻击不会改变现实死亡、攻击目标、同伴、物品、钱、技能、经验或击杀计数。

- 逐步保存及移动/等待中恢复：临时景中的主角与同伴隐藏；回景还原真实原点；错误 origin、错误 sceneKey、加载失败都不能跳步。重试加载只重请求资源，不重复动作奖励。
- 首次楼战没有纳兰固定倒地或普通胜负；海边回调的真儿外观先离去，主角醒后才进入寻找。头像、姓名和同伴都不得提前变成月眉儿。
